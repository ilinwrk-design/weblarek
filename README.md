# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.


## Данные

Все общие типы и интерфейсы приложения находятся в файле `src/types/index.ts`. Это исключает дублирование описаний одинаковых структур в разных частях проекта.

### Тип `TPayment`

```ts
type TPayment = 'card' | 'cash';
```

Описывает доступные способы оплаты заказа: банковской картой при оформлении (`card`) или наличными при получении (`cash`).

### Интерфейс `IProduct`

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Описывает товар каталога:

- `id: string` — уникальный идентификатор товара;
- `description: string` — подробное описание товара;
- `image: string` — относительный путь к изображению;
- `title: string` — название товара;
- `category: string` — категория товара;
- `price: number | null` — цена товара. Значение `null` означает, что товар недоступен для покупки.

### Интерфейс `IBuyer`

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Описывает заполненные и проверенные данные покупателя:

- `payment: TPayment` — выбранный способ оплаты;
- `email: string` — электронная почта покупателя;
- `phone: string` — телефон покупателя;
- `address: string` — адрес доставки.

### Тип `TBuyerData`

Описывает внутреннее состояние модели покупателя во время заполнения форм. В отличие от `IBuyer`, поле `payment` может содержать пустую строку, пока пользователь не выбрал способ оплаты.

### Тип `TBuyerErrors`

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Описывает объект ошибок валидации. В объект включаются только поля, которые не прошли проверку. Значением каждого свойства является текст соответствующей ошибки.

### Интерфейс `IProductsResponse`

Описывает ответ сервера на запрос каталога:

- `total: number` — количество товаров в ответе;
- `items: IProduct[]` — массив товаров.

### Интерфейс `IOrderRequest`

Расширяет `IBuyer` и описывает объект, отправляемый на сервер при оформлении заказа:

- данные покупателя из `IBuyer`;
- `total: number` — общая стоимость заказа;
- `items: string[]` — массив идентификаторов купленных товаров.

### Интерфейс `IOrderResponse`

Описывает ответ сервера после успешного оформления заказа:

- `id: string` — идентификатор созданного заказа;
- `total: number` — подтверждённая сервером стоимость заказа.

## Модели данных

Модели находятся в папке `src/components/Models`. Каждый класс отвечает только за хранение и обработку своей группы данных. Модели не работают с DOM, не выполняют HTTP-запросы и не зависят от компонентов представления или коммуникационного слоя. Для уведомления Презентера об изменениях каждая модель получает через конструктор объект, реализующий интерфейс `IEvents`.

### Класс `Products`

Назначение: хранение каталога товаров и товара, выбранного для подробного отображения.

Конструктор:

- `constructor(events: IEvents)` — принимает брокер событий, через который модель сообщает Презентеру об изменении каталога или выбранного товара.

Поля:

- `items: IProduct[]` — приватный массив всех товаров каталога;
- `selectedItem: IProduct | null` — приватное поле выбранного товара. Содержит `null`, пока товар не выбран;
- `events: IEvents` — приватное поле с брокером событий.

Методы:

- `setItems(items: IProduct[]): void` — сохраняет копию переданного массива товаров и генерирует событие `products:changed`;
- `getItems(): IProduct[]` — возвращает копию массива товаров;
- `getItemById(id: string): IProduct | undefined` — ищет товар по идентификатору и возвращает найденный объект либо `undefined`;
- `setSelectedItem(item: IProduct): void` — сохраняет товар для подробного отображения и генерирует событие `product:selected`;
- `getSelectedItem(): IProduct | null` — возвращает выбранный товар либо `null`.

### Класс `Basket`

Назначение: хранение товаров, выбранных покупателем, проверка их наличия и расчёт данных корзины.

Конструктор:

- `constructor(events: IEvents)` — принимает брокер событий, через который модель сообщает Презентеру об изменении корзины.

Поля:

- `items: IProduct[]` — приватный массив товаров корзины;
- `events: IEvents` — приватное поле с брокером событий.

Методы:

- `getItems(): IProduct[]` — возвращает копию массива товаров корзины;
- `addItem(item: IProduct): void` — добавляет товар и при успешном добавлении генерирует событие `basket:changed`. Товар без цены и уже добавленный товар игнорируются;
- `removeItem(item: IProduct): void` — удаляет переданный товар из корзины и при фактическом удалении генерирует событие `basket:changed`;
- `clear(): void` — полностью очищает корзину и, если в ней были товары, генерирует событие `basket:changed`;
- `getTotal(): number` — возвращает сумму цен всех товаров корзины;
- `getCount(): number` — возвращает количество товаров;
- `hasItem(id: string): boolean` — проверяет наличие товара по идентификатору.

### Класс `Buyer`

Назначение: хранение, частичное обновление, очистка и валидация данных покупателя.

Конструктор:

- `constructor(events: IEvents)` — принимает брокер событий, через который модель сообщает Презентеру об изменении данных покупателя.

Поля:

- `data: TBuyerData` — приватный объект с текущими значениями `payment`, `email`, `phone` и `address`;
- `events: IEvents` — приватное поле с брокером событий.

Методы:

- `setData(data: Partial<TBuyerData>): void` — частично обновляет данные, сохраняет ранее введённые поля и генерирует событие `buyer:changed`;
- `getData(): TBuyerData` — возвращает копию всех текущих данных;
- `clear(): void` — очищает данные покупателя и генерирует событие `buyer:changed`;
- `validate(): TBuyerErrors` — проверяет каждое поле на пустое значение и возвращает объект ошибок;
- `getValidData(): IBuyer | null` — после успешной валидации возвращает данные в формате `IBuyer`; при наличии ошибок возвращает `null`.

## Слой коммуникации

Коммуникационный слой находится в папке `src/components/Communication`. Он изолирует предметные запросы интернет-магазина от базовой реализации HTTP-клиента.

### Класс `WebLarekApi`

Назначение: получение каталога товаров с сервера Web-Larёk и отправка сформированного заказа.

Класс использует композицию: экземпляр базового API передаётся извне через интерфейс `IApi`. Благодаря этому коммуникационный класс не зависит от конкретной реализации HTTP-клиента и не создаёт её самостоятельно.

Конструктор:

- `constructor(api: IApi)` — принимает объект, реализующий методы `get` и `post`. Объект сохраняется в приватном поле `api`.

Поля:

- `api: IApi` — приватная неизменяемая ссылка на HTTP-клиент.

Методы:

- `getProducts(): Promise<IProductsResponse>` — выполняет `GET`-запрос на эндпоинт `/product/` и возвращает промис с количеством и массивом товаров;
- `createOrder(order: IOrderRequest): Promise<IOrderResponse>` — выполняет `POST`-запрос на эндпоинт `/order/`, передаёт данные покупателя, итоговую стоимость и идентификаторы товаров, затем возвращает промис с идентификатором и стоимостью созданного заказа.

`WebLarekApi` не хранит данные каталога или заказа. Полученные товары сохраняются в модель `Products` в основном скрипте приложения.

## Слой представления (View)

Классы слоя представления отвечают только за отображение данных в готовой HTML-разметке и за преобразование действий пользователя в события приложения. Представления не хранят бизнес-данные, не изменяют модели напрямую и не выполняют запросы к серверу. Связь с остальными частями приложения выполняется через брокер событий `IEvents`: пользовательское действие приводит к генерации события, которое затем обрабатывает Презентер в `main.ts`.

Все компоненты представления наследуются от базового класса `Component<T>`, кроме тех случаев, где в иерархии есть собственный специализированный родитель. Карточки наследуются от общего класса `Card`, формы — от общего класса `Form`. Класс `Modal` не является родителем других компонентов: он только отображает переданный ему самостоятельный DOM-компонент внутри модального окна.

### Класс `Page`

Назначение: отображение состояния основной страницы приложения — каталога товаров и счётчика корзины, а также обработка клика пользователя по иконке корзины.

Наследуется от `Component<IPage>`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент страницы и брокер событий.

Поля:

- `basketCounter: HTMLElement` — элемент `.header__basket-counter`, отображающий количество товаров в корзине;
- `catalog: HTMLElement` — контейнер `.gallery`, в котором отображаются карточки каталога;
- `basketButton: HTMLButtonElement` — кнопка `.header__basket`, открывающая корзину;
- `events: IEvents` — брокер событий приложения.

Методы и сеттеры:

- `set counter(value: number)` — отображает количество товаров в корзине;
- `set gallery(items: HTMLElement[])` — заменяет содержимое каталога переданными DOM-элементами карточек.

События:

- `basket:open` — генерируется при клике по иконке корзины.

### Абстрактный класс `Card`

Назначение: общий родитель для компонентов карточек товара. Содержит функциональность, одинаковую для трёх шаблонов карточки: отображение названия и цены товара, хранение идентификатора товара и форматирование отсутствующей цены.

Наследуется от `Component<ICard>`.

Класс не используется напрямую. На его основе создаются `CatalogCard`, `PreviewCard` и `BasketCard`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает корневой DOM-элемент карточки и брокер событий.

Поля:

- `titleElement: HTMLElement` — элемент `.card__title`;
- `priceElement: HTMLElement` — элемент `.card__price`;
- `events: IEvents` — брокер событий;

Методы и сеттеры:

- `set id(value: string)` — записывает идентификатор отображаемого товара в `data-id` корневого DOM-элемента карточки;
- `set title(value: string)` — отображает название товара;
- `set price(value: number | null)` — отображает цену в синапсах, а при значении `null` выводит текст `Бесценно`.

### Класс `CatalogCard`

Назначение: отображение карточки товара в каталоге на главной странице по шаблону `#card-catalog`. При клике сообщает Презентеру, какой товар пользователь хочет открыть для подробного просмотра.

Наследуется от `Card`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает элемент карточки каталога и брокер событий.

Поля:

- `categoryElement: HTMLElement` — элемент `.card__category`;
- `imageElement: HTMLImageElement` — изображение `.card__image`.

Методы и сеттеры:

- `set category(value: string)` — отображает категорию и устанавливает соответствующий модификатор её оформления;
- `set image(value: string)` — устанавливает адрес изображения товара.

События:

- `card:select` — генерируется при клике по карточке и передаёт `id` выбранного товара.

### Класс `PreviewCard`

Назначение: отображение подробной информации о товаре по шаблону `#card-preview`. Компонент показывает изображение, категорию, название, описание, цену и кнопку действия. Состояние кнопки зависит от доступности товара и наличия товара в корзине.

Наследуется от `Card`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает элемент карточки подробного просмотра и брокер событий.

Поля:

- `categoryElement: HTMLElement` — элемент `.card__category`;
- `imageElement: HTMLImageElement` — элемент `.card__image`;
- `descriptionElement: HTMLElement` — элемент `.card__text`;
- `actionButton: HTMLButtonElement` — кнопка `.card__button`;

Методы и сеттеры:

- `set category(value: string)` — отображает категорию товара и её оформление;
- `set image(value: string)` — отображает изображение товара;
- `set description(value: string)` — отображает подробное описание;
- `set buttonText(value: string)` — отображает переданный Презентером текст кнопки (`Купить`, `Удалить из корзины` или `Недоступно`);
- `set buttonDisabled(value: boolean)` — включает или блокирует кнопку действия.

События:

- `preview:action` — генерируется при нажатии на кнопку действия и передаёт `id` товара. Компонент не решает, нужно добавить товар или удалить его: это решение принимает Презентер по данным модели корзины.

### Класс `BasketCard`

Назначение: отображение одной позиции корзины по шаблону `#card-basket`. Показывает порядковый номер товара, название, цену и кнопку удаления.

Наследуется от `Card`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает элемент карточки корзины и брокер событий.

Поля:

- `indexElement: HTMLElement` — элемент `.basket__item-index`;
- `deleteButton: HTMLButtonElement` — кнопка `.basket__item-delete`.

Методы и сеттеры:

- `set index(value: number)` — отображает порядковый номер позиции в корзине.

События:

- `basket:item-remove` — генерируется при клике по кнопке удаления и передаёт `id` товара.

### Класс `BasketView`

Назначение: отображение содержимого корзины по шаблону `#basket`. Компонент показывает список карточек выбранных товаров, общую стоимость и кнопку перехода к оформлению заказа.

Наследуется от `Component<IBasketView>`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент корзины и брокер событий.

Поля:

- `listElement: HTMLElement` — список `.basket__list`;
- `totalElement: HTMLElement` — элемент `.basket__price` с общей стоимостью;
- `orderButton: HTMLButtonElement` — кнопка `.basket__button`;
- `events: IEvents` — брокер событий.

Методы и сеттеры:

- `set items(items: HTMLElement[])` — отображает список карточек корзины; при отсутствии товаров выводит сообщение `Корзина пуста`;
- `set total(value: number)` — отображает общую стоимость товаров;
- `set valid(value: boolean)` — включает или блокирует кнопку оформления в зависимости от наличия товаров.

События:

- `order:open` — генерируется при клике по активной кнопке `Оформить`.

### Класс `Modal`

Назначение: универсальное модальное окно. Компонент отвечает только за открытие, закрытие и отображение переданного DOM-содержимого. Содержимое модального окна является самостоятельным компонентом и не наследуется от `Modal`.

Наследуется от `Component<IModal>`.

Конструктор:

- `constructor(container: HTMLElement, events: IEvents)` — принимает элемент `#modal-container` и брокер событий.

Поля:

- `closeButton: HTMLButtonElement` — кнопка `.modal__close`;
- `contentElement: HTMLElement` — контейнер `.modal__content`;
- `events: IEvents` — брокер событий.

Методы и сеттеры:

- `set content(value: HTMLElement)` — помещает переданный компонент в `.modal__content`;
- `open(): void` — открывает модальное окно;
- `close(): void` — закрывает модальное окно и очищает его содержимое;
- `render(data: IModal): HTMLElement` — устанавливает содержимое и открывает окно.

Пользователь может закрыть окно кликом по крестику или по области overlay вне `.modal__container`.

События:

- `modal:close` — генерируется при клике пользователя по крестику или по overlay. Само закрытие выполняется Презентером вызовом `close()`.

### Абстрактный класс `Form<T>`

Назначение: общий родитель для форм оформления заказа. Содержит общую работу с полями формы, кнопкой отправки, сообщениями об ошибках и преобразованием пользовательского ввода в события.

Наследуется от `Component<T>`.

Класс не используется напрямую. На его основе создаются `OrderForm` и `ContactsForm`.

Конструктор:

- `constructor(container: HTMLFormElement, events: IEvents)` — принимает DOM-элемент формы и брокер событий.

Поля:

- `submitButton: HTMLButtonElement` — кнопка формы с типом `submit`;
- `errorsElement: HTMLElement` — элемент `.form__errors`;
- `events: IEvents` — брокер событий.

Методы и сеттеры:

- `set valid(value: boolean)` — управляет состоянием `disabled` кнопки отправки;
- `set errors(value: string)` — отображает сообщение об ошибке;

Общий класс один раз подписывается на события `input` и `submit` в конструкторе. При вводе он передаёт Презентеру имя изменённого поля и его новое значение. Представление не предоставляет геттеров для чтения данных формы: источником данных остаётся модель покупателя.

### Класс `OrderForm`

События:

- `order:input` — генерируется при изменении поля формы и передаёт объект `{ field, value }`;
- `order:submit` — генерируется при успешной пользовательской отправке первого шага формы.

### Взаимодействие компонентов представления с Презентером

Представления не вызывают методы моделей и API напрямую. Любое действие пользователя преобразуется в событие, после чего Презентер в `main.ts` решает, какие данные изменить и какие компоненты перерисовать.

Основной поток взаимодействия:

```text
Действие пользователя
        ↓
View-компонент
        ↓ emit(...)
EventEmitter
        ↓
Presenter (main.ts)
        ↓
Model / WebLarekApi
        ↓
Presenter
        ↓ render(...)
View-компонент
```

Такое разделение сохраняет слабую связанность классов: представления и модели зависят только от интерфейса событий, модели остаются независимыми от DOM и API, а `main.ts` выполняет роль Презентера и координирует работу приложения.


## События приложения

Все пользовательские действия в слое Представления преобразуются в события и передаются Презентеру. View-компоненты не вызывают модели или API напрямую и не принимают бизнес-решения.

| Событие | Источник | Данные | Назначение |
| --- | --- | --- | --- |
| `basket:open` | `Page` | — | Пользователь нажал на иконку корзины. |
| `card:select` | `CatalogCard` | `{ id: string }` | Пользователь выбрал товар для подробного просмотра. |
| `preview:action` | `PreviewCard` | `{ id: string }` | Пользователь нажал кнопку действия в карточке товара; Презентер решает, добавить товар или удалить. |
| `basket:item-remove` | `BasketCard` | `{ id: string }` | Пользователь нажал кнопку удаления товара из корзины. |
| `order:open` | `BasketView` | — | Пользователь нажал кнопку «Оформить». |
| `modal:close` | `Modal` | — | Пользователь закрыл модальное окно крестиком или кликом по overlay. |
| `order:payment-change` | `OrderForm` | `{ payment: TPayment }` | Пользователь выбрал способ оплаты. |
| `order:input` | `OrderForm` | `{ field: string, value: string }` | Пользователь изменил поле первого шага оформления. |

| `contacts:input` | `ContactsForm` | `{ field: string, value: string }` | Пользователь изменил email или телефон. |

| `products:changed` | `Products` | — | В модели сохранён новый массив товаров каталога. |

## Презентер

В приложении используется один Презентер, потому что Web-ларёк состоит из одной страницы. Код Презентера находится в основном файле `src/main.ts`, отдельный класс для него не создаётся.

Презентер связывает модели данных, компоненты представления и коммуникационный слой через общий экземпляр `EventEmitter`. Он подписывается на события, получает актуальные данные из моделей и передаёт их компонентам представления для отображения.

Презентер сам не генерирует события. Изменение представления выполняется при обработке событий от моделей или при открытии модального окна.

### Отображение каталога

После получения товаров с сервера массив сохраняется в модели `Products` методом `setItems()`. Модель генерирует событие `products:changed`.

Презентер обрабатывает это событие следующим образом:

1. Получает актуальный массив товаров через `productsModel.getItems()`.
2. Для каждого товара клонирует шаблон `#card-catalog`.
3. Создаёт экземпляр `CatalogCard` и передаёт в него данные товара через `render()`.
4. Собирает полученную разметку карточек в массив.
5. Передаёт массив карточек компоненту `Page` через `render({ gallery: cards })`.

Таким образом, запрос к серверу только изменяет данные модели, а перерисовка каталога происходит отдельно при обработке события `products:changed`.

### Открытие карточки товара

При клике по карточке `CatalogCard` генерирует событие `card:select` и передаёт `id` товара. Презентер получает товар из модели методом `getItemById()` и сохраняет его как выбранный с помощью `setSelectedItem()`.

После сохранения выбранного товара модель `Products` генерирует событие `product:selected`. В обработчике этого события Презентер:

1. Получает выбранный товар через `productsModel.getSelectedItem()`.
2. Создаёт `PreviewCard` из шаблона `#card-preview`.
3. Передаёт в карточку данные товара.
4. Если у товара нет цены, передаёт текст кнопки `Недоступно` и блокирует её. Для доступного товара пока отображается кнопка `Купить`.
5. Передаёт готовую карточку в `Modal` и открывает модальное окно.

Компонент `Modal` генерирует событие `modal:close` при клике по крестику или по области вне содержимого окна. Презентер обрабатывает это событие и вызывает метод `modal.close()`.

### Добавление и удаление товара из превью

При нажатии на кнопку подробной карточки `PreviewCard` генерирует событие `preview:action` и передаёт `id` товара. Презентер получает товар из модели каталога и проверяет его наличие в `Basket`.

Если товара ещё нет в корзине, Презентер вызывает `basketModel.addItem()`. Если товар уже есть в корзине, вызывается `basketModel.removeItem()`. Товар без цены не изменяет корзину.

После изменения состава корзины модель `Basket` генерирует событие `basket:changed`. В его обработчике Презентер получает количество товаров методом `basketModel.getCount()` и передаёт новое значение компоненту `Page` для отображения счётчика.

После действия с товаром модальное окно закрывается. При следующем открытии товара текст кнопки определяется по состоянию модели корзины: `Купить` или `Удалить из корзины`. Для товара без цены остаётся кнопка `Недоступно`.


### Открытие и отображение корзины

При нажатии на иконку корзины компонент `Page` генерирует событие `basket:open`. Презентер получает актуальный список товаров из модели `Basket`, создаёт для каждого товара `BasketCard` из шаблона `#card-basket` и передаёт полученные элементы в `BasketView`.

В `BasketView` также передаются общая стоимость корзины и признак наличия товаров. Если корзина пустая, компонент показывает сообщение `Корзина пуста`, а кнопка `Оформить` остаётся заблокированной. После подготовки разметки Презентер открывает её в `Modal`.

При нажатии на кнопку удаления `BasketCard` генерирует событие `basket:item-remove` с `id` товара. Презентер находит товар в каталоге и вызывает `basketModel.removeItem()`. Модель корзины после изменения генерирует `basket:changed`.

В обработчике `basket:changed` Презентер обновляет счётчик товаров на странице. Если корзина в этот момент открыта, её список, итоговая стоимость и состояние кнопки оформления также перерисовываются по актуальным данным модели.

### Первый шаг оформления заказа

При нажатии на кнопку `Оформить` компонент `BasketView` генерирует событие `order:open`. Презентер создаёт `OrderForm` из шаблона `#order`, получает сохранённые данные покупателя из модели `Buyer` и открывает форму в модальном окне.

Выбор способа оплаты генерирует событие `order:payment-change`. Ввод адреса генерирует событие `order:input`. В обоих случаях Презентер сохраняет новое значение в модели `Buyer`.

После сохранения модель генерирует событие `buyer:changed`. В обработчике этого события Презентер снова получает данные и ошибки валидации из модели и передаёт их в `OrderForm`. Кнопка `Далее` становится активной только тогда, когда выбран способ оплаты и заполнен адрес. Ошибка первого незаполненного поля показывается в `.form__errors`.

### Второй шаг оформления заказа

После корректного заполнения первой формы пользователь нажимает кнопку `Далее`. Компонент `OrderForm` генерирует событие `order:submit`. Презентер получает сохранённые данные покупателя из модели `Buyer`, создаёт `ContactsForm` из шаблона `#contacts` и открывает её в модальном окне.

При изменении email или телефона компонент `ContactsForm` генерирует событие `contacts:input`. Презентер определяет изменённое поле и сохраняет новое значение в модели `Buyer`.

После изменения модель `Buyer` генерирует событие `buyer:changed`. Презентер получает актуальные данные и результат валидации. Если открыта форма контактов, в неё передаются email, телефон, сообщение об ошибке и состояние кнопки отправки. Кнопка активна только при заполненных email и телефоне.

### Отправка заказа на сервер

После заполнения формы контактов компонент `ContactsForm` генерирует событие `contacts:submit`. Презентер получает данные покупателя из модели `Buyer`, список товаров и общую стоимость из модели `Basket`.

На основе этих данных формируется объект `IOrderRequest`. В поле `items` передаются идентификаторы товаров из корзины. После этого Презентер вызывает метод `webLarekApi.createOrder()` и передаёт в него сформированный заказ.

При ошибке запроса она обрабатывается в `catch` и выводится в консоль.

### Успешное оформление заказа

После успешного ответа сервера Презентер очищает ссылки на открытые формы, затем вызывает `basketModel.clear()` и `buyerModel.clear()`. Модели очищают сохранённые товары и данные покупателя и генерируют свои события изменения.

После этого Презентер создаёт компонент `Success` из шаблона `#success`. В компонент передаётся итоговая сумма `total`, полученная в ответе сервера. Готовая разметка отображается в `Modal`.

При нажатии на кнопку `За новыми покупками!` компонент `Success` генерирует событие `success:close`. Презентер обрабатывает его и закрывает модальное окно. После очистки корзины счётчик товаров на главной странице становится равен нулю.
